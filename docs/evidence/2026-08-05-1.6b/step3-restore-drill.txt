Step 3 — Restore drill (Neon PITR, LSN-based restore-in-place)
=============================================================
Branch under test: migration-e2e-adopt-<RUN_ID>  (id br-REDACTED)
Date: 2026-08-05

METHOD NOTE — why this differs from the runbook's original Step 3:
- Free-tier Neon PITR retention is 6h, so branching from a pre-cutover timestamp
  (before the 2026-07-31 production cutover) is impossible.
- This neonctl version's `branches create --parent` cannot do a point-in-time
  branch off a NON-default branch: --parent takes a single value (branch, or a
  bare LSN/timestamp that applies only to the DEFAULT branch). `id@lsn` inline
  syntax is not parsed by this version.
- Timestamp-based PITR proved unreliable at second precision (client/server clock
  skew put the restore point AFTER the change). Switched to an LSN captured on the
  server via pg_current_wal_lsn() — exact, skew-immune.
- Gotcha: in Git Bash, `psql` is winpty-wrapped; capturing its output in $(...)
  prints "stdout is not a tty" and yields empty. Use `psql.exe` in command
  substitution to bypass winpty.
- Solution: `neonctl branches restore <branch> ^self@<lsn>` (restore-in-place on
  the branch's own history), with --preserve-under-name to keep the pre-restore
  state as a backup branch.
