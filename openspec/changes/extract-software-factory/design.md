## 2. Secret and sensitivity scan (task 1.2)

The 41 files were scanned for: GitHub, OpenAI-style, AWS and Slack token prefixes; private-key headers; JWT-shaped strings; database connection strings with credentials; email addresses; product names (Clerk, Neon, Doppler, Stripe, Cloudflare, this repo's name); and any URL that is not a GitHub, Anthropic, CodeScene, Node, npm, OpenSpec or licence-source link.

Result: no credential and no live secret. The scan does match the following, all benign:

- **Credential-shaped strings:** `scripts/setup-git-secrets.sh:76-81` holds the _patterns_ `ghp_`, `gho_`, `github_pat_` and `-----BEGIN` that git-secrets is told to block. It is not a secret, and the file stays in this repo (row 21).
- **Email addresses:** `scripts/git-hooks.test.js:19` (`test@example.com`, a placeholder) and the `claude[bot]` noreply address in `factory.yml:197` (the public GitHub App identity).
- **Product names:** prose in `factory.yml:38-39`, `run-spec/SKILL.md:178`, `factory-ci-relay.yml:23`, `pr-feedback.js:99` (a workflow name, row 9), `factory.yml:275` (`doppler` in a deny list, row 12), test fixtures in `factory-route.test.js:107` and `factory-workflows.test.js:38`, and `pre-commit-secrets.sh:46` and `setup-git-secrets.sh:83-88` (which stay). Rows 9, 12 and 14 cover the ones that move.
- **URLs:** test fixtures (`https://github.com/o/r/...`, `https://example.com/runs/1`), this repo's public run URLs in `factory-retry.test.js:7-8` (row 22), and the public git-secrets repo.
- **Personal identifier:** the owner login in row 1, already public on the repo.

The new repo starts from a fresh history: files are copied, not pushed with this repo's history, so no earlier commit can carry anything this scan would have caught in a later version.

## 3. Open design points for tasks 1.3 and later

- **Config schema and adapter contract:** task 1.3 turns the keys above into a JSON schema, and the adapter operations in the spec into a typed contract.
- **Gates are by changed path, not by package.** `gates[].when` takes globs, so a monorepo can run `test:db` only for `workers/**` while a single-package repo has one entry with no `when`.
- **Bot profiles are not built.** `review_bots` names the bots and the skill's notes are generic (row 8). If one bot's behaviour ever needs code, the profile belongs in the factory, not config, and adding it is a factory release; naming an unknown bot needs no release.
