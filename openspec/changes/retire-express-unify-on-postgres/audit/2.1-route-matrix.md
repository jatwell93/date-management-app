# 2.1 — Mounted-Route Matrix

> **Inventory task.** One row per Express method+path and per Worker method+path.
> The `Decision` column carries a mandatory `PROPOSED:` prefix on every row —
> deletion authority is human; this document proposes, it does not decide.
>
> **Source of truth for "mounted?":** `backend/src/index.ts` `app.use(...)` calls
> (39 total). A router file that is never passed to `app.use` is `unmounted/dead`.
>
> **Source of truth for Worker routes:** `workers/src/index-minimal.ts`
> `MINIMAL_API_ROUTES` (lines 194–269) plus the inline health/webhook/upload
> branches in the fetch handler (lines 308–411). `workers/src/index.ts` and
> `workers/src/express-adapter.ts` are an **abandoned** Worker entry point and
> are NOT treated as live; any route reachable only through them is noted but
> not counted as a live Worker route.
>
> **Frontend consumer search method:** `grep -rn "<path>" frontend/src` for each
> route prefix, filtering out `__tests__/` and `.test.` matches where the call
> site is a test mock rather than a real consumer. The frontend's
> `api.service.ts` builds URLs against `API_BASE_URL` (env `REACT_APP_API_URL`,
> default `http://localhost:3001`) and most call sites use bare paths like
> `/products` (mounted at both `/products` and `/api/products` in Express).
>
> **Auth-type legend:**
> - `jwt` — `authenticateToken` middleware (legacy JWT in `Authorization` header).
> - `clerk` — `clerkAuth` / `clerkAuthHandler` middleware (Clerk session JWT).
> - `none` — no auth middleware on the route or its mount.
>
> **Cell convention:** `unknown` means the value could not be determined from the
> code read for this audit. A blank or `unknown` is honest; a guessed value is a
> defect.
